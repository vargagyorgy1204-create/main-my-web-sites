# VarBro site — standing rules for changes

Static HTML/CSS/JS on GitHub Pages (no build step). Pages: `index.html`, `myapproach.html`, `adatvedelem.html`, `whatsappcontact.html`.

1. **Smoke test before every commit — scoped to the change.** **Small, local change (one section / component):** run only the related groups, `node tests/smoke.mjs --only=<group>[,<group>]` (groups: index, pages, touch, hover, layout, header, headingfx, whypin, titles, about; e.g. contact form / footer / buttons -> `index` (+ `hover` if hover or cursor behaviour is touched, `pages` if another page is touched); heading changes -> `headingfx,titles`; Rólam -> `about`; Értékek -> `whypin,hover`; mobile menu / header -> `header,touch`). **Full `--quick`** (default, ~2–3 min: the quick viewport set below, index only) only when **shared CSS tokens**, the **`cursor.js` core** or **several sections** are changed. **Never run `--full`** (whole standard viewport set, all pages, touch-laptop emulation; ~5–7 min or more) **unless the owner asks for it.** **Never run the same suite twice in one task.** Run each test once: no "before" run unless it is a regression hunt; if a check fails, fix it and re-run only that group (`--only=<group>`; a lone failure that does not touch your change, e.g. a 3 px drift in a pinned section under 3 parallel workers, is re-run once on its own before it is treated as real; a run that takes several times longer than usual with many "test run completed" failures means the machine was overloaded: re-run it). Never commit with failures.
   (Needs Playwright with Chromium. If Playwright is not resolvable set `PW_MODULE=/path/to/playwright`; if Chromium is elsewhere set `PW_CHROMIUM=/path/to/chromium`; `/opt/pw-browsers/chromium` is picked up automatically. The run prints its total duration.)
2. **Change only what the task asks.** Do not refactor or rename shared classes, selectors or ids, and do not touch other sections' CSS/JS. If a shared rule must change, list every section that uses it and re-verify each one.
3. **Hover effects are gated by `html.has-cursor`** (set by `cursor.js` on the first real mouse move), never by `@media (hover: hover) and (pointer: fine)` — touch-screen laptops report those as false. Touch devices use tap / in-view behaviour without hover.
4. **After every change** bump the `?v=` cache-bust versions of every changed asset in ALL html files, then commit, push, and report (the report is written in Ukrainian; site copy stays Hungarian, Ön-form).
5. Do not call `ScrollTrigger.refresh()` manually (it cancels in-flight Lenis anchor scrolls). Do not commit the untracked `photo1–4.jpg` in the repo root.
6. Global rules from `~/.claude/CLAUDE.md` still apply (Lucide icons via CDN, static HTML default).
7. **Proportional layout system:** read `DESIGN-SYSTEM.md` before any layout / size change. All sizes are fluid tokens from the reference viewport 1440x900, defined once in the `DESIGN TOKENS` block of `style.css`; sections only use tokens (a new value = a new token + an updated table in `DESIGN-SYSTEM.md`). Pinned sections must fit one viewport on every standard viewport, also the short-wide ones (1518x670, 1366x768).
8. **Review board — never automatic.** `node tests/board.mjs` (screenshots of every section x every standard viewport -> `board/index.html`, git-ignored) is run ONLY when the owner explicitly asks for the "board" / "дошка скріншотів". Then report the path to `board/index.html` and list the sections / viewports that changed visibly (pixel diff vs the previous board run > 2%; the script prints them; portfolio cells are animated and always show some noise).

## Viewports (tests/smoke.mjs)

- **Standard set (`--full`):** phones 360x800, 390x844, 430x932; tablet 768x1024; laptops 1280x720, 1366x768, 1536x864; desktop 1440x900, 1920x1080; **the owner's real Chrome viewport 1518x670** (a 1920x1080 screen at Windows display scaling 125%: CSS px, not the 1897x840 you would measure at 100%). 2560x1440 only for the `titles` group.
- **Quick set (`--quick`, the full-quick run of rule 1; the viewports every `--only` group also uses):** 390x844, 1366x768, 1440x900, 1518x670.
- **Rules:** every layout / proportion change is verified on the **quick set**; changes to shared tokens or to the layout of several sections are verified with the full `--quick` run; the **full set (`--full`) only when the owner asks**. Heights below ~700px (1518x670 is the owner's) are the tightest case: check them first for anything that must fit one viewport.
- **Reporting:** the run prints a per-viewport table (checks / failed); copy it into the report (in Ukrainian) so the owner can see which viewport fails.
